Optimisation du code intermédiaire
Une étape clé du processus de compilation visant à améliorer l'efficacité du programme sans en
modifier la sémantique.
Elle intervient après la génération du code intermédiaire et avant la génération du code machine.
Son objectif est d'optimiser l'exécution du code en le rendant plus rapide et moins
consommateur de ressources, sans en altérer les fonctionnalités.

Parmi ces opérations, on trouve:
Propagation de copie
Propagation d’expressions
Élimination des expressions redondantes
Simplification algébrique
Élimination de code inutile

1. Propagation de copie
Une technique qui consiste à remplacer une variable par sa valeur ou une autre variable à
laquelle elle a été affectée.
Cela permet d'éliminer les affectations inutiles et d'améliorer l'efficacité du code.
Principe:
Lorsqu'une variable x est affectée à une autre variable y (y = x), on peut directement remplacer y par
x dans le reste du programme (si aucune autre affectation ne modifie x ou y entre-temps).

Cas où la propagation n'est pas possible:
Elle n'est pas possible si la variable affectée change avant d'être utilisée.
Exemple:
t1= t2 ;
t1= t3;

❌ Propagation de copie impossible

t4= t1 + t5 ;
La propagation de t1 = t2; est inutile car t1 est écrasé immédiatement après avec t1 = t3;.
Si on remplaçait t1 par t2 dans t4 = t1 + t5;, cela donnerait t4 = t2 + t5;, ce qui serait incorrect, car t1 a
été modifié avant d'être utilisé.
La bonne valeur de t1 lors de son utilisation est t3, donc seule la dernière affectation est pertinente.

2. Propagation d’expression
Principe:
Si une variable stocke une expression mais n'est utilisée qu'une seule fois, alors il est inutile de la
garder. On peut directement remplacer son utilisation par l'expression qu'elle contenait.
Exemple:
Avant optimisation:

Après optimisation:

t1= expr;

t3= 4* expr ;

t3= 4* t1 ;

Remarque:
Si la même expression est utilisée plusieurs fois, alors il vaut mieux garder la variable pour éviter de
recalculer plusieurs fois.

3. Élimination des expressions redondantes (ou
communes)
Principe:
Cette technique consiste à éviter de recalculer une expression si elle a déjà été évaluée
auparavant et que ses variables n’ont pas changé. Au lieu de recalculer, on réutilise le résultat
stocké dans une variable temporaire.
Autrement dit,
Si une expression E apparaît plusieurs fois et que les variables qui la composent n’ont pas été
modifiées, on remplace ses occurrences suivantes par la variable qui stockait E.

Exemple:
Avant optimisation:
t1 = a + b;
t2 = c * d;
t3 = a + b; // Redondant, car déjà calculé dans t1
t4 = t3 * e;

Après optimisation:
t1 = a + b;
t2 = c * d;
t4 = t1 * e; // Remplacement de t3 par t1

a + b est recalculé une deuxième fois (t3 = a + b;), ce qui est inutile.
Donc, on évite un recalcul en réutilisant t1 au lieu de recalculer a + b.
Remarque:
Si l'une des variables de l'expression change entre deux utilisations, la valeur recalculée peut être
différente et l’optimisation ne peut pas être appliquée.
